## 1. 产品概述 (Overview)

### 1.1 产品定义
**VerbaFlow (AI 语流)** 是一款 **本地优先 (Local-First)** 的专业级音视频内容校对与术语管理套件。它利用大语言模型（LLM）的多模态能力，辅助内容创作者、译者和校对人员进行高效的字幕校对、术语一致性检查及文稿润色。

### 1.2 核心价值主张
*   **隐私安全 (Privacy)**：无后端架构，所有文件（视频、音频、字幕）和数据库均存储在用户浏览器本地 (IndexedDB)，仅在分析时将必要数据发送至 LLM 服务商。
*   **专业工作流 (Workflow)**：不仅仅是聊天机器人，而是深度集成了播放器控制、字幕编辑器和术语库管理的垂直领域工具。
*   **人机回环 (Human-in-the-Loop)**：支持对 AI 结果进行微调、备注，并反哺给 AI 进行二次校对，确保最终结果的精准。

## 2. 功能需求 (Functional Requirements)

### 2.1 项目管理 (Project Management)
*   **FR-001 新建项目**：用户可创建新项目，系统自动分配唯一 ID 和时间戳。
*   **FR-002 项目列表**：展示所有历史项目，支持按更新时间排序。列表项应包含：项目名、当前进度状态（Step）、最后编辑时间、摘要预览。
*   **FR-003 数据持久化**：所有项目状态（包括未保存的输入）应自动保存至 IndexedDB，防止意外关闭导致数据丢失。
*   **FR-004 导入/导出**：支持导出项目为 `.vfproj` (JSON) 文件，支持从文件导入完整项目状态。

### 2.2 素材上传与配置 (Upload & Config)
*   **FR-005 多模态上传**：支持上传 视频 (.mp4, .mov)、音频 (.mp3, .wav) 和 字幕 (.srt, .vtt, .ass)。
*   **FR-006 云端集成**：支持通过 Google Drive Picker 直接选择云端文件，无需下载到本地（需处理 OAuth Token）。
*   **FR-007 模型配置**：允许用户在项目内临时切换模型（如从 Flash 切换到 Pro），并设置目标输出语言。
*   **FR-008 上下文预设 (New)**：在分析开始前，允许用户输入“全局背景信息”并指定“主要输出语言”。**注意：该语言设置必须强制应用于后续的内容摘要生成。**

### 2.3 智能分析与校对 (Analysis & Proofreading)
*   **FR-009 全局分析**：LLM 读取字幕（及音视频上下文），提取关键术语，并生成摘要。
*   **FR-010 术语校对表 (Enhanced)**：
    *   交互式表格：`时间轴 | 原文 | AI建议修正 | 状态 | 详情`。
    *   **详情编辑**：支持点击每行编辑，查看原文上下文，手动修改修正结果，并添加 **用户备注 (User Note)**。
    *   状态流转：`待确认` -> `已确认` / `需人工复核` / `需 AI 再次确认`。
*   **FR-011 智能重分析 (Re-Analyze)**：
    *   用户可在校对界面输入新的指令（如“重新检查人名”）。
    *   AI 会结合当前表格状态进行增量更新。
*   **FR-012 媒体同步与播放器优化 (Revamped)**：
    *   **统一媒体引擎**：系统底层必须维护单一 `<video>` 实例，无论当前是视频视图还是音频视图。切换视图时，**严禁** 销毁播放器实例，以实现 0 延迟切换和状态保持。
    *   **智能控制栏**：
        *   控制栏仅保留全局操作（播放/暂停、进度、模式切换）。
        *   辅助功能（字幕开关、自动滚动锁定）应下沉至播放器画面内的悬浮层。
    *   **画中画 (PiP)**：必须支持视频小窗播放，且在切换至音频模式（看歌词）时，画中画窗口不应被强制关闭。

### 2.4 术语库管理 (Glossary Management)
*   **FR-013 术语集管理**：用户可创建多个术语集（如“医疗类”、“游戏类”）。
*   **FR-014 智能提取入库 (New)**：支持从分析结果表中，将“已确认”的术语一键提取并保存到指定术语集。
*   **FR-015 闭环优化**：在进行新项目分析时，可勾选已有的术语集。

### 2.5 字幕与文稿生成 (Generation)
*   **FR-016 字幕重写**：基于确认的术语表，让 AI 重新生成 SRT 文件。**严禁输出非字幕内容的废话 (Conversational Filler)。**
*   **FR-017 文稿润色**：将字幕转换为通顺的 Markdown 文章。
*   **FR-018 下载与导出**：支持直接下载生成的 .srt 和 .md 文件。

### 2.6 语流助手 (AI Assistant / Chat)
*   **FR-019 上下文感知**：助手应知晓当前项目的内容。
*   **FR-020 悬浮窗交互**：聊天窗口可拖拽、缩放、贴边隐藏，不遮挡工作区。

## 3. 非功能性需求 (Non-Functional Requirements)

### 3.1 性能 (Performance)
*   **NFR-001 启动速度**：应用首屏加载时间 (FCP) 应小于 1.5秒。
*   **NFR-002 大文件处理**：支持处理 2小时以上的长视频/音频，UI 不应卡顿。
*   **NFR-003 内存管理 (Critical)**：对于 Blob URL 资源，必须在组件卸载或文件变更时强制执行 `revokeObjectURL`，防止 SPA 长期运行导致内存泄漏崩溃。

### 3.2 兼容性 (Compatibility)
*   **NFR-004 浏览器**：支持 Chrome (推荐), Edge, Safari, Firefox 最新版。
*   **NFR-005 响应式**：核心功能需适配桌面端 (Desktop)，部分查看功能适配移动端。

### 3.3 安全与隐私 (Security)
*   **NFR-006 API Key 存储**：API Key 仅存储在 LocalStorage，禁止上传至任何中间服务器。
*   **NFR-007 数据隔离**：不同用户的浏览器环境数据物理隔离。

## 4. 路线图 (Roadmap)

### Phase 1: MVP (Completed)
*   基础的项目 CRUD。
*   Gemini/OpenAI 接入。
*   SRT 解析与同步播放。
*   基础术语提取。

### Phase 2: 专业化 (Current)
*   完善 IndexedDB 缓存机制。
*   **人机回环**：术语提取入库、单条备注、增量重分析。
*   **预处理**：上传阶段的上下文注入。
*   **播放器增强**：统一媒体引擎、无缝切换、歌词模式。
*   **输出质量控制**：严格限制 AI 输出格式。

### Phase 3: 高级功能 (Planned)
*   **波形图可视化**：在播放器下方展示音频波形。
*   **本地模型支持**：通过 WebLLM 或 Ollama 接入本地运行的模型（真正离线隐私）。
*   **多模型竞技场**：同时使用两个模型分析并对比结果。
